# 共享资源与设计

## 分层

1. `styles/tokens.css`：颜色、字体、间距、圆角等设计变量。实验可局部覆盖变量。
2. `styles/base.css`：基本排版、按钮、表单、焦点样式。实验自己的样式放在实验目录。
3. `js/`：不绑定某一学科的工具，例如全屏、重置流程。
4. `components/`：经多个实验验证的地图控制、时间轴、问答面板等组件，每个组件附使用说明。
5. `assets/`：跨实验使用的素材，记录作者、来源和授权。
6. `vendor/<name>/<version>/`：第三方库的浏览器构建文件。保留 LICENSE 和来源说明，禁止使用不固定版本的 `latest` 地址。

## 第三方类库

按实验需要选择地图、图表、3D 或动画类库。浏览器可直接导入的库优先采用 ES Modules；需要构建工具的实验可独立配置，并在其 README 中说明启动方式。根目录服务不会编译 TypeScript 或解析 npm 裸模块名。

新增共享库时在 `shared/vendor/registry.json` 登记名称、准确版本、文件路径、来源 URL 与许可证，在实验的 `experiment.json` 的 `libraries` 数组记录使用的版本。不默认联网下载资源，也不要求全部实验加载所有共享库。

已有固定依赖通过 `npm ci` 安装，`npm run vendor` 从锁定的 npm 包复制浏览器构建；`npm run build` 自动调用该同步步骤。GSAP 的官方许可证页面单独保存在 vendor 中，不在构建或运行时联网请求。新增库时应同时补齐包内许可证或来源说明。

案例的 `sharedAssets` 只声明自有共享文件，第三方库通过 `libraries` 声明。下载包保留所需的共享路径，不把所有已安装类库都装进每个案例。选择类库时优先考虑教学表现力、设备兼容性与资源体积，而非一律追求零依赖。

## 课堂设计

- 字号和交互目标适合投屏，关键结论不单靠颜色区分。
- 交互有清晰操作提示，重要状态可重置，动画尊重减少动态效果偏好。
- 学科模型说明简化条件，数据标注来源和时间。
- 需要离线授课时，将许可允许的类库、字体、数据与素材本地化并断网验证。HTML 文件本身不保证离线可用。
- 每个实验记录学习目标、适用年级、预计时长、交互方式和课堂反馈。
